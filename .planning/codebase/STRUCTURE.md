## Directory Purposes

**`backend/cmd/server/`:**
- Purpose: Application entry point
- Contains: main.go with server initialization logic
- Key files: `main.go` (route definitions, middleware, service startup)

**`backend/internal/database/`:**
- Purpose: Data persistence layer abstraction
- Contains: PostgreSQL connection management and query builders
- Key files: `db.go` (connection pool, CRUD methods, search queries)

**`backend/internal/handlers/`:**
- Purpose: HTTP request processing and business logic coordination
- Contains: Handler methods for all API endpoints
- Key files: `handlers.go` (songs CRUD, search, admin operations, ProPresenter endpoints)

**`backend/internal/models/`:**
- Purpose: Domain types and request/response schemas
- Contains: Struct definitions with JSON serialization tags
- Key files: `song.go` (Song, CreateSongRequest, UpdateSongRequest)

**`backend/internal/typesense/`:**
- Purpose: Full-text search integration
- Contains: Typesense client initialization, schema definition, indexing/search methods
- Key files: `client.go` (collection schema, indexing, search queries)

**`backend/internal/propresenter/`:**
- Purpose: Optional presentation software integration
- Contains: HTTP client for ProPresenter REST API
- Key files: `client.go` (library queries, playlist management, item triggering)

**`backend/internal/backup/`:**
- Purpose: Database persistence and recovery
- Contains: Backup scheduling (daily + on edit threshold)
- Key files: `backup.go` (pg_dump execution, file management)

**`backend/migrations/`:**
- Purpose: Database schema versioning
- Contains: SQL files for schema creation and updates
- Key files: Initial schema files (version-based naming)

**`frontend/app/`:**
- Purpose: Next.js page routing and root layout
- Contains: Root page component and per-route page components
- Key files: `page.tsx` (control window), `display/page.tsx` (display window), `layout.tsx` (wrapper)

**`frontend/components/`:**
- Purpose: Reusable React components
- Contains: UI components for search, forms, display, lists
- Key files:
  - `SearchBar.tsx` (search input + language filter buttons)
  - `SongForm.tsx` (create/edit song modal)
  - `SongList.tsx` (scrollable songs list)
  - `SplitLyricsView.tsx` (multi-pane lyrics with drag resizing)

**`frontend/lib/`:**
- Purpose: Utility libraries and API integration
- Contains: Axios client with type-safe service objects
- Key files: `api.ts` (axios instance, service objects for songs/admin/propresenter)

**`frontend/public/`:**
- Purpose: Static assets served as-is
- Contains: Fonts, images, favicons
- Key files: `fonts/` (custom typefaces)

## Naming Conventions

**Files:**
- Go: `snake_case.go` (e.g., `song.go`, `backup.go`)
- TypeScript/React: `PascalCase.tsx` for components, `camelCase.ts` for utilities (e.g., `SearchBar.tsx`, `api.ts`)
- SQL: `YYYYMMDD_description.sql` (version-numbered migrations, if following standard convention)

**Directories:**
- Go internal packages: `lowercase` (e.g., `handlers`, `database`, `models`)
- React components: `PascalCase` (e.g., `components/`)
- Next.js app routes: `lowercase/page.tsx` structure (e.g., `app/page.tsx`, `app/display/page.tsx`)

**Functions/Methods:**
- Go: `PascalCase` for exported, `camelCase` for unexported (e.g., `CreateSong`, `reorderByLanguage`)
- TypeScript: `camelCase` for functions and variables (e.g., `handleSearch`, `loadSongs`)

**Variables:**
- React state: `camelCase` with hook naming (e.g., `selectedSong`, `setSongs`, `isLoading`)
- Go packages: imported with full path, used with package prefix (e.g., `database.New()`, `models.Song`)

**Types:**
- Go structs: `PascalCase` (e.g., `Song`, `Handler`, `DB`)
- TypeScript interfaces: `PascalCase` with or without "I" prefix convention not used (e.g., `Song`, `SearchResult`)

## Where to Add New Code

**New Song Feature (e.g., rating, tags, categories):**
- Add field to `Song` struct in `backend/internal/models/song.go`
- Update database schema in `backend/migrations/` with ALTER TABLE
- Update SQL queries in `backend/internal/database/db.go` (CreateSong, GetSong, UpdateSong)
- Update Typesense schema in `backend/internal/typesense/client.go` (Field definition)
- Add handler logic in `backend/internal/handlers/handlers.go`
- Add TypeScript interface in `frontend/lib/api.ts`
- Update React components in `frontend/components/` (SongForm, SongList) to display/edit new field

**New API Endpoint:**
- Handler method: Add to `backend/internal/handlers/handlers.go` as `(h *Handler) MethodName(c *fiber.Ctx) error`
- Route registration: Add to `backend/cmd/server/main.go` in route setup section
- API client: Add method to appropriate service object in `frontend/lib/api.ts` (or create new object)
- Frontend component: Use new API method via imported service object

**New React Component:**
- Create file in `frontend/components/ComponentName.tsx` with `'use client'` directive if using hooks
- Define TypeScript interface for props
- Export default function component
- Import and use in parent components

**New Integration (e.g., new external API):**
- Backend: Create `backend/internal/[service]/client.go` with HTTP client and methods
- Initialize in `backend/cmd/server/main.go` main() function
- Create handler methods for integration endpoints in `backend/internal/handlers/handlers.go`
- Register routes in `backend/cmd/server/main.go`
- Frontend: Add service object to `frontend/lib/api.ts`
- Use in React components via imported service

**Database Queries:**
- Add method to `backend/internal/database/db.go` (receiver on DB struct)
- Follow pattern: func (db *DB) MethodName(...) (..., error) { ... }
- Use prepared statements or parameterized queries ($1, $2, etc.)

**Utility Functions:**
- Backend: Add to `backend/internal/handlers/handlers.go` as unexported helpers (lowercase function names) or create new file in appropriate package
- Frontend: Add to `frontend/lib/api.ts` for API-related utilities, or create new file in `frontend/lib/`
